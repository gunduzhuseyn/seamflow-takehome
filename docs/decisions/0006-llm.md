# LLM feature

## Context

The product has one LLM action: classify an image. It runs in the worker,
and the browser polls for the result (decisions/0008). The result is
structured, validated, and stored with a record of the call. The provider
sits behind a small interface, so a second provider is one file. The
template streamed a note summary over SSE; this project removed that path.

## Decision

- **Interface.** `app/llm/provider.py` defines `LLMRequest` and the events
  `TextDelta`, `ToolInput`, `Usage`, and `Error`. A provider has one method:
  `stream(request)`. `app/llm/anthropic_provider.py` uses the Anthropic SDK.
  `app/llm/fake_provider.py` replays `tests/fixtures/llm/*.json`. The
  lifespan builds one provider from `LLM_PROVIDER` and puts it on
  `app.state`, like the sessionmaker. Production requires `anthropic`.
- **Structured output.** One tool per call. Its schema comes from a Pydantic
  model, and the same model validates the tool input. The request sends
  `tool_choice: auto` with `strict: true`, because the current models
  reject a forced tool choice. The prompt names the tool. A reply with no
  tool call, or one that fails validation, is stored as `invalid_output`
  with the raw text in `error`.
- **Prompts are files** in `app/llm/prompts/`, with a `version: N` first
  line. The version goes into the call record.
- **Outcome.** `app/llm/calls.py` consumes the provider stream, validates
  the tool input, and returns the output or a code: `invalid_output`,
  `refusal`, `max_tokens`, `provider_error`, `timeout`. No SSE: the
  browser polls the row the call belongs to.
- **Record.** `llm_calls` gets one row per call, inserted as `running`
  before the call starts and updated when it ends. The row carries
  `subject_id`, the id of the row the call is about, with no foreign key.
  It also carries the request id from the `X-Request-Id` middleware, the
  model, tokens, cost, latency, result, and error. `GET /llm-calls/{id}`
  returns one row.
- **Cost** comes from a price table in `app/llm/prices.py`, USD per million
  tokens by model. The API returns token counts, not prices. A new model
  or price is a table edit.
- **Retries and timeout** are the SDK's `max_retries` and `timeout`, set
  from `LLM_MAX_RETRIES` and `LLM_TIMEOUT_SECONDS`. `app/llm/complete.py`
  adds one retry on invalid output only, with a row per attempt.
- **Limits**, all settings: `LLM_MAX_IMAGE_BYTES`, a cap on the resized
  model input, checked in the worker before the call; `LLM_MAX_OUTPUT_TOKENS`;
  and `LLM_RATE_LIMIT_PER_MINUTE` per user, counted in Redis at the request.
  Over the rate limit: 429, with no row.
- **Prompt re-run.** The `live` pytest marker is reserved for tests that
  call the real provider. The default `addopts` excludes it. The vision
  unit adds the first such test.
- **Logs** are JSON lines from the standard library. One line per LLM call
  carries the request id, call id, model, status, tokens, cost, and latency.

## Consequences

- A second provider implements `stream()` in one file and is chosen by
  `LLM_PROVIDER`.
- Tests run on the fake provider with real Postgres and Redis. One adapter
  test replays a canned SSE stream through the SDK with an injected transport.
- The price table goes stale when prices change. The pricing page is the
  source; the file names the date it was read.
